# 発音チェック方式 試作(プロトタイプ)

English-LevelUp-Reader の「発音チェック」機能について、**クラウドAPIを使わず、ブラウザの中だけで
Whisper(音声認識モデル)をWebAssemblyで動かす方式**が、実用に足る精度・速度で動くかどうかを
本実装の前に確認するための試作品です。

## なぜこの試作が必要か(経緯)

- 姉妹アプリ `English-Speaking-App` はブラウザ標準の音声認識API(Web Speech API /
  `webkitSpeechRecognition`)を使っているが、iPhoneのSafariで認識精度が悪いという指摘があった。
- そのため本アプリでは、クラウドAPI(有料・APIキー管理の問題あり)ではなく、
  **ブラウザ内でWhisperモデルを動かす方式**(無料・音声データを外部送信しない)を採用する方針とした。
- ただし、この方式は今回が初めての試みであり、実際にどの程度の精度・速度が出るかは未検証。
  そこで本実装(全レベルへの組み込み)の前に、小さな試作で確認する。

## ⚠️ 開発環境(このセッション)で実機テストできなかった理由

このプロトタイプ用のコード自体は作成しましたが、**私(Claude)が作業しているクラウド上の開発サンドボックスから、
モデルファイルの配信元である `huggingface.co` と、ライブラリ配信元の `cdn.jsdelivr.net` への通信が、
組織のネットワークポリシーによりブロックされている**ことを確認しました
(`curl`で接続確認したところ `403 CONNECT tunnel failed` )。

これはあくまで**私の開発用サンドボックスの制約**であり、実際にこのアプリを使う方(ユーザーの手元のPC)の
ブラウザは通常のインターネット接続を持っているため、この制約の影響を受けません。
そのため、**このプロトタイプの精度・速度の確認は、お手数ですがユーザーご自身のPCで実施していただく
必要があります。**

## 試し方

1. このリポジトリを clone するか、`prototype/whisper-test.html` をダウンロードする。
2. マイクの使用がブラウザで許可されるよう、**ローカルサーバー経由**で開いてください
   (`file://` で直接開くとマイクが使えないブラウザがあります)。
   ```bash
   cd prototype
   python3 -m http.server 8000
   ```
   その後ブラウザで `http://localhost:8000/whisper-test.html` を開く。
3. 「① モデルを読み込む」ボタンを押す(初回は数十MBのダウンロードが走るので少し待つ)。
4. 「🎤 録音開始」→ 画面上のお手本文を声に出して読む → 「■ 録音停止して認識」。
5. 認識結果・認識にかかった秒数・簡易的な単語一致率が表示される。

## 確認していただきたいポイント

- **精度**: 実際に話した内容が、それなりに正しく文字起こしされるか(特に日本語話者の英語発音で)。
- **速度**: モデル読み込み・認識それぞれ何秒くらいかかるか(体感で許容できる速さか)。
- **`whisper-tiny.en` と `whisper-base.en` の比較**: 精度と速度のどちらを優先すべきか。
- そのほか気になった点(エラーが出た、マイクが使えない、など)。

これらの結果を教えていただいた上で、本実装(全レベルへの組み込み)に進めるかどうかを一緒に判断させてください。
